## A2 · ALTA — La auditoría diaria dice "sin hallazgos" con un check que no corrió

existe `frontend/node_modules`:

```python

    return []          # sin dependencias no se puede afirmar nada, ni bueno ni malo
```

El comentario es honesto, pero el **reporte no lo es**: "no se puede afirmar nada"
sale impreso idéntico a "pasó". En este worktree no hay `node_modules`, así que el
check tardó 0.0s y la auditoría cerró con "sin hallazgos".

Por qué importa hoy y no en abstracto: **el commit más reciente de `main` es
`9f7ec50 fix: revert Leads.jsx to fix build error`**. El dashboard se rompió, y se
arregló revirtiendo. Es exactamente el fallo que este check existe para pescar, y
en la corrida de hoy habría guardado silencio.

Cobertura real: `.github/workflows/tests.yml` (job `frontend`) sí hace `npm ci` +
`vite build`. Pero corre solo en push a `main` y en PR — y `scripts/dia.sh` commitea
en ramas de workspace **sin hacer push**. El ciclo autónomo, que es justo el que
escribe JSX sin que nadie mire, es el que no tiene esa red.

**Qué hacer:**
- Que `auditar.py` distinga tres estados por check: `ok` / `hallazgo` / `omitido`, y
  que el resumen final nombre lo omitido en vez de callarlo.
- Que `dia.sh` corra `npm ci` una vez antes de auditar, o que el check omitido sea
  hallazgo de gravedad media en lugar de silencio.
