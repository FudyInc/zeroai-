## L1 · MEDIA — El archivo de auditoría guarda los números y pierde el porqué

`68bf54b` existe para responder *"si algo lleva tres semanas roto o si se rompió anoche"*.
Guarda `docs/auditoria/YYYY-MM-DD.json` en `audit/diaria`. Pero:

```
$ git ls-tree -r --name-only audit/diaria -- docs/auditoria/
docs/auditoria/2026-09-04.json          ← solo el JSON mecánico
```

Los informes de criterio —los `.md` que explican *por qué* algo está roto y qué hacer—
viven en `docs/auditoria/*.md` sobre `FudyInc/AUDIT`. **Dos ramas reclaman el mismo
directorio y ninguna ve a la otra.** No hay conflicto de archivos (`.json` vs `.md`), pero
sí de historia: quien abra `audit/diaria` en tres semanas encuentra ocho días de
`"hallazgos": 0` y nada que le diga que el ciclo llevaba seis días sin ejecutar una tarea
— porque eso el auditor mecánico no lo mide, y es justo lo que estos informes registran.

El archivo cumple su promesa literal y se queda corto en la que importa.

**Detalle menor, del mismo commit:** el padre se elige así (`commitear-auditoria.sh:35`):

```bash
BASE="$(git rev-parse --verify --quiet "refs/heads/$RAMA" || git rev-parse --verify main)"
```

Tras el primer día, `BASE` es siempre la rama misma, así que el árbol queda congelado en
el `main` del día 1 (`19d54b6`) para siempre, con los JSON encima. Funciona, pero en un mes
`audit/diaria` es una copia completa del repo de septiembre con archivos sueltos añadidos.
Una rama huérfana (`commit-tree` sin padre, árbol solo con `docs/auditoria/`) haría lo
mismo sin arrastrar el repo entero. No corre prisa; anotado para cuando se toque.

## M1 · MEDIA — El archivo crea un commit por corrida, no uno por día

`commitear-auditoria.sh` tiene una guarda explícita para no ensuciar el historial:

```bash
if [ "$TREE" = "$(git rev-parse "$BASE^{tree}")" ]; then
  echo "  sin cambios respecto a $RAMA — no se crea commit"
```

**No puede dispararse nunca.** El JSON lleva marca de tiempo y duraciones, así que el árbol
siempre difiere. Hoy quedaron dos commits para la misma fecha:

```
$ git log --oneline audit/diaria | head -2
197238b audit: informe del 2026-09-04 (0 hallazgos, 0 altos)
6107408 audit: informe del 2026-09-04 (0 hallazgos, 0 altos)

$ git diff 6107408 197238b -- docs/auditoria/2026-09-04.json
-  "cuando": 1788449982.5556836
+  "cuando": 1788534959.0863366
-      "segundos": 20.3
+      "segundos": 20.5
```

Dos mensajes de commit idénticos, dos árboles distintos, cero información nueva. Con una
corrida diaria son 365 commits al año donde se querían 365; con dos, son 730. El historial
que este commit venía a construir se llena de ruido justo por la línea que existía para
evitarlo.

**Arreglo barato:** comparar solo los campos que importan —`hallazgos`, o los `checks` sin
`segundos`— en vez del árbol completo. O `--amend` cuando ya hay commit para esa fecha, que
además deja un commit por día como promete el nombre del archivo.

Esto no invalida `68bf54b`: el mecanismo funciona, main queda intacta, el JSON se archiva.
Es un defecto de una línea en una pieza que por lo demás hace lo que dice.
